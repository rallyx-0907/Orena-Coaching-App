# ORENA UI AGENT RULES
## Short mandatory rules for any AI touching learner-facing UI

Read the authoritative product/design files first:

1. `docs/project/PRODUCT_CONSTITUTION.md`
2. `docs/project/DESIGN_CONTRACT.md`
3. current verified product state / handoff files required by repository governance

Do not treat screenshots, legacy UI or old code as product authority when they conflict with those contracts.

## Core direction

- Clarity first.
- Curiosity next.
- Depth over time.
- Simple front door, deep world behind it.
- Less words, more life.
- Artwork is a system, not decoration.
- Content-first, not feature-dashboard-first.
- Guided learning and exploration must coexist.
- AI stays backstage.
- English and Chinese are first-class.

## Never

- redesign from a blank canvas without inspecting existing contracts/assets;
- use `eyebrow + huge headline + slogan + paragraph + mascot` as a default template;
- add copy to compensate for weak composition;
- turn the "world" idea into fantasy/lore;
- rename clear navigation into vague poetic phrases;
- scatter unrelated artwork styles;
- ship letter/geometry placeholders as production content art;
- add mascot art only to fill empty space;
- make every component a white rounded SaaS card;
- duplicate one content item into separate skill silos unless the data model explicitly requires it;
- hide core learner actions behind scrolling;
- regress mobile, English or Chinese.

## Artwork

Before UI implementation, determine the approved Art Bible for:

- mascot;
- scenes;
- thumbnails;
- book covers;
- icons;
- backgrounds/patterns;
- motion.

Prefer actual content imagery and coherent designed artwork over generic decoration.

Vivid color is encouraged when controlled by the system.

## New learner rule

A person who has never learned a language and never used a learning app must know what to do next within a few seconds.

Always preserve an obvious:

- Start;
- Continue;
- or equivalent primary action.

Do not require the learner to understand product philosophy.

## Discover rule

Discover should expose interesting content and continuity, not merely repeat the navigation taxonomy.

Reading/Listening shortcuts may remain, but they must not be the only organizing principle.

## Focus rule

Inside Reader/Listening/Writing/Speaking:

- reduce shell/navigation noise;
- prioritize the content/task;
- keep explanations and learning tools close;
- avoid decorative distraction.

## Review test

Before calling work done:

1. Remove slogans mentally. Is the screen still clear and alive?
2. Remove labels Reading/Listening/Speaking/Writing mentally. Does Discover still contain reasons to explore?
3. Can a complete beginner find the next action?
4. Does the artwork look like one product?
5. Are imagery and icons doing more work than prose?
6. Does mobile preserve the same meaning without excessive scrolling?
7. Are English and Chinese both verified?
