## How the copy was made

`DesignSync get_file` caps a file at 256 KiB. `Orena.dc.html` is 832 485 bytes,
so the tool returned only its first 262 144 bytes (25 of 63 frames, no mobile
tab bar, no sheets and none of the state script). The human exported the whole
project to disk on 2026-09-27; that export is what is pinned here. Its first
262 144 bytes are byte-identical to what DesignSync returned, and
`Onboarding.dc.html`, `Compare With Model.dc.html`, `Orena Admin.dc.html` and
`support.js` are byte-identical to their DesignSync reads.

A future re-pin diffs against these bytes (`PINS.tsv`). When a file is still over
256 KiB, get it from an export, not from DesignSync.

## Reading the file

The markup between `<x-dc>` tags is a template: `{{ }}` values and handlers come
from `class Component` in the state script at the end of the file;
`<sc-if>`/`<sc-for>` render conditionally and repeat; `style-hover` and
`style-active` are the hover and pressed styles. Device and theme are CSS
variables on `body[data-device=desktop|mobile]` and
`body[data-theme=dark|light]`; `body[data-focus=1]` is a learning workspace
(no top bar, no tab bar). The strip above the frame (Desktop / Mobile, Light /
Dark) is prototype chrome, not product UI.

To render it offline: serve this folder (`python -m http.server 8765 --bind
127.0.0.1` from `docs/design/canonical-ui/screens`) and open `Orena.dc.html`.
The desktop frame fills the window (it is not scaled); the phone frame is drawn
1:1 at 390x844.

Sample content — lessons, sentences, names, numbers, the "Calis" avatar — is
not data (D-068) and never reaches the product.
