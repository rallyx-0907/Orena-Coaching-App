## Rules the cache did not carry

- **One app.** The design's own `CLAUDE.md`: a new screen improves on what already exists and never replaces
  it with a narrower set of features; names, navigation and vocabulary already in use are kept. (The product
  speaks the learner's language setting, D-068; the frames' Vietnamese is sample text.)
- **Two frames only** (desktop 1920x1080 shown at 62%, mobile 390x844). No intermediate breakpoint, no tablet.
- **Height budget, worked out before a row is added.** Desktop 1080 - top bar 84 - padding 26/34 = 936px for
  content. Mobile 844 - header ~99 - footer ~109 = ~636px for the scrolling area. Every `overflow:hidden`
  region must have `scrollHeight === clientHeight`.
- **Pattern 8 and 9.** On a phone the sheet is the last `flex:none` child of the screen and the dimmed area
  above it is a `flex:1` spacer - never a pixel `top`. Inside a `flex:1;min-height:0` container exactly one
  child is `flex:1`; otherwise the spare room becomes an empty band.
- **Loading, Empty, Error have no canonical design** (`states.md`): a known gap, not a defect. Modal/Drawer,
  Profile, My Content, Admin, Onboarding and the tablet are INCOMPLETE too.
